Career Garden — how it works

A job-search workspace that tracks applications, researches the interview process from public sources, builds a deadline-aware preparation plan, and rehearses answers. React/Vite SPA + Netlify Functions + Supabase, with an optional Gemini/Brave AI layer.

1 · The core loop — one job, four steps

01

Track

Save a job: company, role, stage, dates, links, notes. Six plant stages (Seed → New beginning), list & board views, activity log.

→
02

Research

Authenticated fetch of the JD, catalogue + search discovery, polite crawl of allowlisted hosts, AI extraction of interview accounts. Sources stay unreviewed until you confirm them.

→
03

Prepare

Deadline-aware plan: timezone-aware slots, 15% buffer, dependency-greedy scheduler, bounded JD matching, direct learning links.

→
04

Practice

Role-specific prompts, timer, dictation, self-review; optional AI coaching with quoted-evidence validation. Saved attempts feed back into the plan.

workflow.js → synchronizePreparation() is the single transition shared by job edits, research, and practice reviews. A planning failure never blocks saving — it returns an actionable notice.

2 · System architecture

Client (browser)

React 19 SPA. Landing page, Google PKCE login, authenticated workspace. src/AppNew.jsx, src/career/*.

Storage

Demo = browser localStorage. Cloud = Supabase jobs table with optimistic revision concurrency. repository.js.

API (Netlify Functions)

Three authenticated endpoints. Vite serves them locally via vite.config.js; netlify.toml maps them in production.

3 · Request pipeline — POST /api/career-research

POST body→ validateInput (size/length)→ Bearer token → Supabase getUser→ claim_career_research() quota (8/hr)→ read JD (safe-source)→ seed catalogue + Brave search→ polite crawl (robots + rate limit)→ Gemini extract accounts (exact-substring spans)→ 200 JSON (jd, sources, accounts, warnings)
gate / boundary honest partial states (no fabricated results)

4 · Evidence & scheduling core (deterministic, no LLM)

assembleProcessMap()

Hard exclusions (wrong company, unread body, unapproved rights, private-source ownership, missing provenance), event-based freshness, dedup by independence group, separate variants, format-confirmation flags. Scores order evidence — not probabilities.

schedulePreparation()

Absolute timestamps, dependency DAG with cycle detection, buffer, per-slot & overall budget, prerequisite promotion, completed-task preservation, explicit deferred[] work. Oversized mocks are deferred, never split silently.

src/lib/prepEngine.js — rank weights 0.55 scope fit + 0.25 freshness + 0.20 source weight; "historical" begins at 365 days (UI heuristic, not a factual expiry).
